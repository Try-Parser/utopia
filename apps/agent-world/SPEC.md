The server is loopback-only. Operator configuration chooses one workspace and whether workspace edits may be requested. HTTP clients cannot choose executables, paths, models, arbitrary command arguments, or sandbox bypass flags. A live request has `requestId` (32 lowercase hex characters), `title` (1–100 nonblank characters), `brief` (0–600 characters), `role` (one of the six world roles), `access` (`read-only` or `workspace-write`), and optional `provider` (a validated provider id). Provider omission is allowed only when the request can unambiguously resolve to one available adapter or reconcile an existing job. Other fields are rejected. Edit access is denied unless enabled by the server. Specialist review/design roles remain read-only; only coordinator and builder can receive edit tasks.

POST requests require the exact local Origin, Host, JSON content type, bounded Content-Length, and the server's session token. Duplicate request IDs with identical payloads return the same job, including after a lost response; changed payloads conflict. The queue processes one job at a time and refuses additional requests when ten unfinished jobs are present. The persisted history holds at most 100 terminal and unfinished jobs, with bounded output and activity events. A replay key remains attached to its retained job.

Jobs progress through queued, starting, running, then completed, failed, cancelled, timed-out, or interrupted. Only an observed successful turn-completed event, final response, and zero process exit allow completed. Completed means the agent turn ended, not tests/reviews passed. Tool failures are visible as activity. Raw commands, tool outputs, reasoning and credentials are not persisted. A final agent answer is retained locally as the requested result.

Each run uses a server-owned provider adapter and an argument array with shell execution disabled. Codex retains `exec --json --ephemeral --sandbox <access> --cd <configured-workspace> -` and approval policy never. Claude uses print/stream-json, restricted mode, no session persistence and explicit built-in file tools; read-only omits editing tools, while workspace-write adds Edit/Write. This initial Claude adapter has no shell, MCP or delegation capability and requires support for the restricted flag. Unsupported versions fail instead of relaxing permissions. Prompt text goes through stdin. Canonical role guidance and repository instructions apply; tasks cannot authorize commits, pushes, deployment or external messages through this interface. Installed CLIs enforce their own access modes and use their existing accounts. Development verification never invokes real Claude or other model providers.

Mission provider contract v1 (`mission-providers.contract.json`) defines detection and selection. The native snapshot includes a bounded providers list with opaque id, label, installed/available state, allowed accessModes and an explanatory reason. Detection refreshes through read-only PATH and bounded per-user installation entrypoints, without running a CLI or reading account settings. Recognized installed tools without a launch adapter remain visible as adapter-needed and cannot receive missions. Availability means an executable was found, not that account authentication succeeded.

New requests include a provider id. For compatibility, omission resolves only the sole available launch adapter; multiple available providers require a choice. The form restores an available last choice, otherwise selects the sole available provider or prompts for a choice. A mission's provider is pinned in history and idempotency, preserved in office employees and results, and never silently switched on failure or removal. Retried retained request IDs reconcile the original provider before availability checks. A definitive pre-queue LiveError rejection returns accepted=false so the form can accept another choice; network loss or an unknown server failure retains the original request/provider until reconciliation. Existing history without a provider is migrated from the former Codex-only runner; an explicit unknown id is never relabeled. Browser inputs never supply executable paths or arbitrary arguments.

Cancellation removes queued work or terminates the owned process tree. Each task has a configured timeout. Shutdown cancels owned work. On restart, unfinished persisted jobs become interrupted, with unknown prior process outcome; never replay automatically. History lives under an operator-chosen private data directory outside source and workflow evidence folders. The browser does not retain credentials or native results in localStorage.

Verification covers real subprocess protocol fixtures, HTTP boundaries, idempotency, queue/cancellation, failure/timeout/restart, bounded data and actual Chromium journeys. A separate read-only native account smoke may establish real connection; fixtures do not establish account access or live AI quality.

## Automatic live office, version 1

Only explicitly role-reported idle sessions follow a cosmetic waiting routine through reception and the shared break corridor; they may visit their own workstation. Process-only sightings stay in the Local sessions journal and never become floor avatars. Identified sessions without a current task event wait in reception without roaming. Roaming never sets working, assigns an unknown role, emits a handoff, or executes a task. A confirmed working assignment or handoff preempts roaming on the same avatar. Workstation destinations align workers with chair fronts; extra workstations, cabinets, printers and server racks have matching collision bounds.

Scene movement is enabled by default unless the operating system requests reduced motion. Pause movement/Play movement controls it independently of real task processing; explicit Play can opt into movement under a reduced-motion preference. Idle movement pauses at its current position, while confirmed assignments can be placed directly at their destinations without animation. Simulation pause stops its scene as well as its illustrative work. Cosmetic motion is identified in the visible office HUD and remains distinct from provider-reported activity.

The scene is the primary viewport surface. The live/demo selector and connection health remain visible in a compact header; source details expand without exposing additional metadata. The worker inspector opens from a scene character or Workers button, closes with Escape or its close button, and returns focus to the initiating control. Source changes close the inspector. Tasks and activity occupy a collapsible journal tray; assignment opens the tray, while its results remain the existing safe read-only/native UI. Mobile starts with the complete office overview and provides an explicit closer view. Visual scaling changes sprite size, never logical movement coordinates or role/handoff semantics. Pixel-style office and characters use local SVG/CSS assets.

The default view observes native task events and detected local sessions together. Stable session IDs own avatars; native tasks own avatars by job ID. Native turns use assigned roles. Process-only entries have unknown task/role; provider identity, file freshness, workspace and prompt text never establish a department. Bounded structured local tool events may instead place a session in an activity department, explicitly distinguished from an assigned specialist role (ADR0013). Historical records do not create workers without exact live-session correlation or a fresh structured active Codex turn.

The existing heartbeat keeps its required five fields. Optional fields are `role` (planner/designer/builder/reviewer/qa/security), `taskId` (1–80 token characters), `handoffTo` (same role enum), and `eventId` (1–80 token characters). A handoff requires role, taskId and eventId. Unknown fields and malformed types are rejected. Task IDs and event IDs are served only as opaque hashes. All metadata remains in memory, with the existing heartbeat expiry and an at-most-80-event, five-minute handoff journal. Repeating an identical retained event is idempotent; conflicting reuse is rejected. A handoff is adapter-reported routing evidence, never permission to launch the next agent or proof that tests passed.

Working agents walk to their confirmed department. Role changes move the same avatar, and explicit handoffs move a task packet and the sending avatar toward the next department. Waiting, idle, ended and stale activity remain distinct. Native turn completion does not invent a next specialist. Switching sources clears obsolete avatars and handoff animations. Reduced motion places avatars at their destination and shows static routing evidence. The illustrative simulation visibly demonstrates planning → design → build → independent review/QA/security → handoff, using its own clearly labeled synthetic work.

## Local session discovery, version 1

Discovery is read-only and enabled independently of native execution. It combines accessible OS process signatures, bounded metadata from configured Codex/Claude session roots, and authenticated provider-neutral heartbeats. Unknown providers can supply heartbeats or an operator can configure `Provider=executable-name`. Never invoke Claude or another provider runtime to discover it.

Keep process and session entries distinct. A running app process may contain multiple hidden threads or no active conversation. Only an explicit session UUID in recognized process arguments correlates it with a stored session; never join by workspace or file freshness. File updates are labeled recent metadata, not working agents. Generic heartbeats are labeled adapter-reported working/waiting/idle/ended, stale after 30 seconds and removed after five minutes. No inferred task names, progress, model usage or review outcomes.

Return only opaque IDs, provider/alias, source kind, evidence status, workspace basename, PID/parent PID and observation timestamp. No raw command arguments, executable paths, prompts, message bodies, session titles, credentials or reasoning are persisted or served by discovery. OS command arguments are read transiently for runtime entrypoints/resume UUIDs. Session headers are read in bounded projections and immediately discarded. Deny symlinks and junctions; never read account configuration or authentication files.

Cache OS/record scans for five seconds. Bound OS entries, directory traversal, file headers and returned inventory; show partial scans explicitly and retain source availability states. Refresh removes disappeared process entries. Collector failure clears process evidence while preserving separately observed session records with unknown runtime activity. Hidden browser/cloud threads, container/WSL namespaces and protected processes need an explicit metadata adapter; do not claim universal coverage.

Heartbeat requests have exactly provider, sessionId, state, workspace and pid; metadata text never becomes a path, command or URL. Require local Origin/Host, JSON body limits and a discovery session token. This metadata endpoint does not grant execution, cancellation or control of external sessions. The GUI lists read-only session metadata in the office journal and only marks fresh reported work as working. Native task controls are available in the same office, while metadata entries grant no execution rights.
