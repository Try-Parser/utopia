# Live agent contract, version 1

The office is the single live workspace, combining native jobs and local sessions on the floor with read-only recorded checkpoints in its journal. A Live workspace / Demo simulation selector keeps illustrative activity distinct. New task assigns a native Codex run to one selected specialist without changing its existing access boundary. Characters use real subprocess or explicitly reported activity; checkpoints never imply per-agent work.

The server is loopback-only. Operator configuration chooses one workspace and whether workspace edits may be requested. HTTP clients cannot choose executables, paths, models, arbitrary command arguments, or sandbox bypass flags. A live request has exactly `requestId` (32 lowercase hex characters), `title` (1–100 nonblank characters), `brief` (0–600 characters), `role` (one of the six world roles), and `access` (`read-only` or `workspace-write`). Edit access is denied unless enabled by the server. Specialist review/design roles remain read-only; only coordinator and builder can receive edit tasks.

POST requests require the exact local Origin, Host, JSON content type, bounded Content-Length, and the server's session token. Duplicate request IDs with identical payloads return the same job, including after a lost response; changed payloads conflict. The queue processes one job at a time and refuses additional requests when ten unfinished jobs are present. The persisted history holds at most 100 terminal and unfinished jobs, with bounded output and activity events. A replay key remains attached to its retained job.

Jobs progress through queued, starting, running, then completed, failed, cancelled, timed-out, or interrupted. Only an observed successful turn-completed event, final response, and zero process exit allow completed. Completed means the agent turn ended, not tests/reviews passed. Tool failures are visible as activity. Raw commands, tool outputs, reasoning and credentials are not persisted. A final agent answer is retained locally as the requested result.

Each run uses `codex exec --json --ephemeral --sandbox <access> --cd <configured-workspace> -`, with approval policy never. No shell interpolation and no Claude invocation. Prompt text goes through stdin. Canonical role guidance and repository workflow instructions apply; tasks cannot authorize commits, pushes, deployment or external messages through this interface. Codex remains responsible for native sandbox enforcement. Authentication uses the installed CLI's existing account.

Cancellation removes queued work or terminates the owned process tree. Each task has a configured timeout. Shutdown cancels owned work. On restart, unfinished persisted jobs become interrupted, with unknown prior process outcome; never replay automatically. History lives under an operator-chosen private data directory outside source and workflow evidence folders. The browser does not retain credentials or native results in localStorage.

Verification covers real subprocess protocol fixtures, HTTP boundaries, idempotency, queue/cancellation, failure/timeout/restart, bounded data and actual Chromium journeys. A separate read-only native account smoke may establish real connection; fixtures do not establish account access or live AI quality.

## Workstation displays, version 1

Six department pairs of computer screens are selectable. Main monitors project the current native task status, reported change count, activity and answer; side monitors open a user-connected local app preview. The enlarged display has Code & activity and App preview views, keyboard focus return, and stable user input while task snapshots refresh. Simulated screens are labeled illustrative. External role-only metadata does not invent code or terminal output.

Native completed file-change events may retain up to twenty scoped relative file labels and add/update/delete kinds. Paths outside the configured workspace, aliases/symlinks, private dot paths and sensitive filename patterns are excluded. Raw patches, commands, stderr, tool output and reasoning are not persisted. The authenticated local GET `/api/live/missions/<job>/changes/<index>` resolves only a retained reported file, never an arbitrary query path. A timed output-bounded Git reader supplies at most 24,000 bytes of current text diff; files or Git baseline blobs above 256,000 bytes are unavailable. Disable external diff, text conversion, fsmonitor and lazy object fetch. Current diffs can contain earlier workspace edits; never attribute the whole patch to the selected task. Binary/unavailable/truncated states are explicit.

App preview requires an explicit user-entered loopback HTTP address on a different port. The server does not fetch it or launch a development service. One iframe, sandboxed for scripts and its own origin only, moves between the enlarged display and the matching small office monitor. URLs stay in browser memory, without localStorage or server history. Local app live reload can update the view; embedding restrictions or a stopped app remain browser limitations. Preview content is independent of simulated/native task evidence. CSP permits frame sources only from localhost/127.0.0.1; the local UI rejects remote hosts, credentials, non-HTTP schemes and its own port.

## Automatic live office, version 1

Only explicitly role-reported idle sessions follow a cosmetic waiting routine through reception and the shared break corridor; they may visit their own workstation. Process-only sightings stay in the Local sessions journal and never become floor avatars. Identified sessions without a current task event wait in reception without roaming. Roaming never sets working, assigns an unknown role, emits a handoff, or executes a task. A confirmed working assignment or handoff preempts roaming on the same avatar. Workstation destinations align workers with chair fronts; extra workstations, cabinets, printers and server racks have matching collision bounds.

Scene movement is enabled by default unless the operating system requests reduced motion. Pause movement/Play movement controls it independently of real task processing; explicit Play can opt into movement under a reduced-motion preference. Idle movement pauses at its current position, while confirmed assignments can be placed directly at their destinations without animation. Simulation pause stops its scene as well as its illustrative work. Cosmetic motion is identified in the visible office HUD and remains distinct from provider-reported activity.

The scene is the primary viewport surface. The live/demo selector and connection health remain visible in a compact header; source details expand without exposing additional metadata. The worker inspector opens from a scene character or Workers button, closes with Escape or its close button, and returns focus to the initiating control. Source changes close the inspector. Tasks and activity occupy a collapsible journal tray; assignment opens the tray, while its results remain the existing safe read-only/native UI. Mobile starts with the complete office overview and provides an explicit closer view. Visual scaling changes sprite size, never logical movement coordinates or role/handoff semantics. Pixel-style office and characters use local SVG/CSS assets.

The default view observes native task events and detected local sessions together. Stable session IDs own avatars; native tasks own avatars by job ID. Native turns use assigned roles. Process-only entries have unknown task/role; provider identity, file freshness, workspace and prompt text never establish a department. Bounded structured local tool events may instead place a session in an activity department, explicitly distinguished from an assigned specialist role (ADR0013). Historical records do not create workers without exact live-session correlation or a fresh structured active Codex turn.

The existing heartbeat keeps its required five fields. Optional fields are `role` (planner/designer/builder/reviewer/qa/security), `taskId` (1–80 token characters), `handoffTo` (same role enum), and `eventId` (1–80 token characters). A handoff requires role, taskId and eventId. Unknown fields and malformed types are rejected. Task IDs and event IDs are served only as opaque hashes. All metadata remains in memory, with the existing heartbeat expiry and an at-most-80-event, five-minute handoff journal. Repeating an identical retained event is idempotent; conflicting reuse is rejected. A handoff is adapter-reported routing evidence, never permission to launch the next agent or proof that tests passed.

Working agents walk to their confirmed department. Role changes move the same avatar, and explicit handoffs move a task packet and the sending avatar toward the next department. Waiting, idle, ended and stale activity remain distinct. Native turn completion does not invent a next specialist. Switching sources clears obsolete avatars and handoff animations. Reduced motion places avatars at their destination and shows static routing evidence. The illustrative simulation visibly demonstrates planning → design → build → independent review/QA/security → handoff, using its own clearly labeled synthetic work.

## Playable office, version 1

The player explores the office using WASD, arrows, pointer floor destinations or movement buttons. Logical foot coordinates collide with desks, chairs, glass dividers, counters and floor bounds. Pointer routes use a bounded grid search. E or Talk opens a nearby character conversation; selecting a character also opens it as an accessible alternative. Conversations offer explicit mission assignment through the existing form. Movement never sends execution requests.

Keyboard controls apply only to the focused floor; dialog/input focus, window blur and hidden tabs clear movement. Conversations close with Escape and restore floor focus. Movement buttons support pointer cancellation and keyboard holds. Reduced motion suppresses decorative walking animation. The map scroll follows player movement on narrow screens.

Onboarding quests track meeting a character, assigning a simulated mission and simulated completion. SIM XP is cosmetic and derived only from simulated completed missions. Local evidence and native tasks retain their original provenance, read-only/opt-in access, and completion semantics. Game progress never asserts a real review or test passed.

## Local session discovery, version 1

Discovery is read-only and enabled independently of native execution. It combines accessible OS process signatures, bounded metadata from configured Codex/Claude session roots, and authenticated provider-neutral heartbeats. Unknown providers can supply heartbeats or an operator can configure `Provider=executable-name`. Never invoke Claude or another provider runtime to discover it.

Keep process and session entries distinct. A running app process may contain multiple hidden threads or no active conversation. Only an explicit session UUID in recognized process arguments correlates it with a stored session; never join by workspace or file freshness. File updates are labeled recent metadata, not working agents. Generic heartbeats are labeled adapter-reported working/waiting/idle/ended, stale after 30 seconds and removed after five minutes. No inferred task names, progress, model usage or review outcomes.

Return only opaque IDs, provider/alias, source kind, evidence status, workspace basename, PID/parent PID and observation timestamp. No raw command arguments, executable paths, prompts, message bodies, session titles, credentials or reasoning are persisted or served by discovery. OS command arguments are read transiently for runtime entrypoints/resume UUIDs. Session headers are read in bounded projections and immediately discarded. Deny symlinks and junctions; never read account configuration or authentication files.

Cache OS/record scans for five seconds. Bound OS entries, directory traversal, file headers and returned inventory; show partial scans explicitly and retain source availability states. Refresh removes disappeared process entries. Collector failure clears process evidence while preserving separately observed session records with unknown runtime activity. Hidden browser/cloud threads, container/WSL namespaces and protected processes need an explicit metadata adapter; do not claim universal coverage.

Heartbeat requests have exactly provider, sessionId, state, workspace and pid; metadata text never becomes a path, command or URL. Require local Origin/Host, JSON body limits and a discovery session token. This metadata endpoint does not grant execution, cancellation or control of external sessions. The GUI lists read-only session metadata in the office journal and only marks fresh reported work as working. Native task controls are available in the same office, while metadata entries grant no execution rights.

## Department workstations and expanding floor

Live office starts with two equally sized, numbered computers per department and grows each department to accommodate every role-known actor in the validated local inventory. Capacity and workstation keys remain stable during the current office visit; active workers have priority over retained native results. New rows enlarge the department, corridor placement and floor height together. The same layout supplies the visual furniture, walkable geometry, actor destinations and monitor coordinates. No fixed two-seat queue or twenty-four-avatar display cap remains. Unknown roles stay in expanded reception without inventing department assignments.

Working characters walk to their assigned computer and display the seated pose only on arrival. Each monitor projects its exact actor, and the workstation selector includes newly added computers. Independent local app previews remain owner-bound; reassignment disconnects the previous preview. The conference room remains connected, with tables/chairs blocking movement. Expanded maps scroll vertically at a usable desktop/mobile scale. Other source/demo views preserve their original fixed scene. Layout observations never execute providers, change native queue execution, or invent meetings or code.

## Task action and colleague representation

Optional heartbeat taskLabel is an explicitly supplied single-line display name of1-100 characters, never read from transcripts. Work details require role and taskId. Action is one of planning/designing/coding/reviewing/testing/auditing/helping/command/research/tool/coordination/reporting. A role alone never implies an action. Native job action derives only from recognized structured item types, with command execution represented as Terminal and file change as Coding.

Helping requires an exact targetProvider+targetSessionId pair, or a native targetJobId of32 lowercase hex characters, never both. Provider/session references are normalized and served only as opaque targetRef with targetKind=session; native public job IDs use targetKind=job. Targets do not authorize execution. Self-session targets, incomplete references, unsupported actions and invalid labels are rejected before mutation. Action/label/target metadata expires with the existing30-second heartbeat; no work text is read from stored provider transcripts.

Helpers visit a free point beside the exact connected working colleague, retain their home computer/role and show a link. An unavailable target produces an explicit waiting state at home, without a guessed substitute. Handoff packets and carriers show the reported task label and recipient/department. Sender role/home computer is unchanged until a new role is reported. Missing recipients produce a department destination, never an invented receiving person. Pending animations do not certify completion.

Worker action/task badges, distinct small props, an inspector destination/relationship description and an expandable Task flow list show current work. Identical titles do not merge tasks. Flow lists up to24 workers and eight recent reported transfers; all actors remain inspectable. Unconnected processes remain in the Local sessions journal; identified sessions without task events wait in reception. Only role-reported idle routines remain cosmetic. Text is rendered with textContent; local previews, code-reader access and native queue authorization are unchanged.

Explicitly role-reported idle characters may walk reception, corridor and coffee routes as a labelled visual waiting routine. Unknown departments stay unassigned and stationary; process-only detections do not create characters. Cosmetic walking never claims tasks, collaboration or meetings. Reported working actors stay at their computers or explicit help/handoff destinations. Pause movement and reduced-motion settings also apply to waiting routines.
