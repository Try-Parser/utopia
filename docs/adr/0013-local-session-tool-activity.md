# 0013: Place local sessions by structured tool activity

Status: accepted for local implementation, 2026-10-13.

The user requested automatic connection of real local coding activity after detecting that working sessions were shown walking in the corridor. Under that authorization, the coordinator adopts a bounded metadata projection of locally accessible structured events. This extends the reported-role model in [0011](0011-autonomous-agent-office.md); native authorization and computer preview boundaries in [0012](0012-workstation-code-and-app-preview.md) remain unchanged.

The user subsequently requested the actual CLI/extension text. A separate, token-protected, selected-session transcript endpoint reads only a bounded tail of the exact local Claude or Codex JSONL file. The office feed and broad session stream keep fixed metadata labels; raw text appears only when a worker or its computer is inspected. Content is rendered as text, never HTML, and is not written to Agent World history. A transcript quiet for thirty seconds is labelled last recorded; after five minutes it is unavailable as current output. Runtime telemetry alone cannot reconstruct the extension's text stream, so that view states its limitation rather than inventing output.

Read fixed event/tool categories and lifecycle signals from bounded primary session tails. Exact live Claude session correlation is required. Fresh structured Codex turns may be observed without a process link, which is disclosed. A tool-category department means an activity placement, never an inferred specialist identity. Explicit role heartbeats retain precedence. Session IDs and activity references remain opaque; no prompts, arguments, outputs, commands, code or input file paths are projected. Do not invoke a provider or change its configuration.

Some Codex app sessions update local runtime records while their rollout file remains stale. For these, project an exact thread ID from bounded runtime log targets as recently observed activity, with fixed Turn activity and Tool activity timeline labels. Thread update timestamps can also advance on terminal persistence, so they must not establish a working state. Fresh explicit tool events or adapter reports take precedence. Never project runtime log bodies, thread titles or message content.

Adapter-only detection preserves privacy but leaves ordinary working sessions unclassified. Using process presence, file freshness or prompt interpretation would invent activity. The bounded metadata allowlist retains source provenance and unknown states when evidence is unavailable; it does not infer collaboration or meetings. Transcript display is a distinct user-requested read of the selected local session and does not establish task state.

The contract is in [Agent World SPEC](../../apps/agent-world/SPEC.md). Docker discovery/model and actual HTTP/Chromium journeys must verify classification, completion, expiry, malformed/bounded input, adapter precedence and private-field exclusion. Independent correctness, QA and security attestations are required before delivery. Revisit if provider event schemas change, supported tools expand, or exact subagent identities become available. This record grants no deployment or paid-provider authorization.
