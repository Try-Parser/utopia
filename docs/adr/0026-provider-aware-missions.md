# Detect and select local mission providers

Status: Accepted direction from the user's explicit provider-neutral mission request.

The former task queue launched Codex for every new mission even though session observation could identify other providers. The user requires available local AI tools to be detected automatically and missions to use the selected provider. Installation detection and session observation remain separate: neither process presence nor finding an executable establishes authentication or current task details.

Use a registry of fixed provider adapters and bounded filesystem-only installation detection. Public metadata contains provider id, name, installed/runnable state, supported access modes and reason; executable paths remain server-side. Implement Codex and Claude native mission adapters, and truthfully mark other recognized installed tools that need an adapter. A generic executable name cannot safely determine its invocation, output protocol or permissions, so arbitrary browser-supplied commands are rejected.

Select the sole runnable provider automatically, or restore an available previous choice. With several providers and no previous choice, ask the user to select one. Pin provider identity to the retained request/job and include it in idempotency, history and office employee provenance. Reconcile retries before detection changes, and never switch a queued job to another provider. Existing history without a provider is known Codex history; explicit unknown providers keep their identity.

Commands are argument arrays with shell execution disabled. Existing Codex sandbox/protocol flags remain. Claude follows its [documented CLI](https://code.claude.com/docs/en/cli-reference) restricted print/stream-json mode with explicit file tools and no session persistence. Read-only excludes editing tools; workspace-write adds Edit/Write. This initial Claude adapter does not expose shell, MCP or delegation tools. Necessary unsupported flags, authentication, permission and process failures fail visibly without bypass or fallback. Both adapters normalize bounded safe activity, visible answers and scoped file labels; reasoning, raw tool input/output, stderr and credentials remain excluded.

The workspace's development workflow still runs only native Codex agents and Docker offline subprocess fixtures; building user-selected Claude execution does not authorize invoking Claude for our engineering work. Tests must cover both fake protocols, argument/access boundaries, discovery arrival/removal, provider-pinned retries, error completion, cancellation, timeouts, history migration, privacy and desktop/mobile selection. An actual-host read-only check establishes installation detection only; do not claim that fixtures authenticated real provider accounts.
