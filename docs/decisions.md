# Shared workflow decisions

Status: accepted for this implementation, 07 October 2026.

The starting repository contained only .gitignore. Canonical sources come from the team's existing autonomous-development, craftsman, frank, commit-pr-standard and six Frank specialist definitions. Portability changes remove private model pins, personal personas, service-specific release assumptions and account data. The four core skills remain; research/design/evaluation are conditional additions.

Three independent review lenses remain required for substantive engineering at every risk tier. Smaller changes reduce context and verification depth. Maximum two automatic fix rounds, fresh final-snapshot attestations, batched blockers and bounded transient retries replace inconsistent small-tier and carry-forward instructions. Actual test evidence can be reused with relevant input/runtime validity; stale verdicts cannot.

Precommit snapshot identity remains strict. The staged tree is recorded so postcommit can compare reviewed content without confusing a normal HEAD change with new content. Hooks, content filters, hidden Git flags and submodules are handled explicitly, not bypassed.

Installation copies canonical content into native assistant locations and generates role/scorer copies from one source. Dry-run is default; conflict replacement requires explicit apply/replace and verified backups. Existing account configuration and root instruction files are never overwritten automatically.

Claude and Codex discussed the design through multiple bounded read-only consultations. Claude independently researched statistics/evaluation and proposed task-based confidence gates, dataset predeclaration, paired comparisons and correlation caveats. Codex retained existing mandatory reviews and corrected unsupported assumptions about roles/staging.

Adopt now: concise sufficient context, independent outcome grading, reusable test evidence, observable checkpoints, role ownership, held-out dataset provenance, conservative repeated-trial aggregation and measured latency/cost. Defer hash-chained evidence logs, fixed token ceilings, mandatory repeated paid trials and additional interval methods until measured need justifies their complexity. Hash chains alone do not prove honest evidence.

The 95%+ objective is a measured task-quality target; the lower two-sided 95% Wilson bound must meet it, and integrity/critical gates must all pass. No live accuracy result is claimed from implementation or synthetic fixtures.

Changes are published to a feature branch. A push request does not imply merging main, enabling repository CI settings, deployment or external messaging.
