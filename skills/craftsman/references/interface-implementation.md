# Interface implementation

Use for assigned UI code changes. Follow existing components, tokens and content hierarchy. Use semantic controls, keyboard navigation, visible focus, appropriate contrast and reduced-motion behavior according to the project's accessibility target.

Exercise relevant populated, loading, empty, error, disabled and permission states. Check long content, supported viewports and persisted readback where applicable. Explain disabled states and recovery actions. Automated audits supplement actual interaction and manual accessibility checks.

Use design-workflow and frank-designer when substantive journeys or visual decisions need a design handoff; small corrections can follow existing patterns. Screenshots show appearance and do not establish interaction or complete accessibility compliance.
